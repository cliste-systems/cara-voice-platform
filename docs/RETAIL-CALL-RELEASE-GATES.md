# Retail call release gates

A passing lookup batch is not a production-ready spoken assistant. Verify these layers independently:

1. **Source to publication:** every fresh, date-current product promotion with matching product, price, mechanic, conditions and dates across at least three public stores must be discoverable through the national offer lookup. Positive evidence can publish during running scans. Absence and retirement still require complete scans. Reject failed sources, stale observations, future/expired validity, fewer than three stores and unresolved price conflicts. Preserve simultaneous mechanics and unrelated published offers.
2. **Price meaning:** `retail_catalog_products.national_regular_price_eur` is a historical regular/reference amount. A range-only fallback must not expose it as a current price or conclude there is no promotion. Current quotes require current listing/promotion evidence, exact product identity and the correct pack or per-kilo unit.
3. **Conversation:** replay broad department → preference → counter/prepack → offer → quantity/savings questions. Unspecified steaks need a species question; never silently choose pork. Explicit beef, pork, cut, preparation and location constraints must survive follow-ups. Test every department, with unavailable and ambiguous products as well as successful matches.
4. **Actual model and audio:** run the actual demo model against real tools and then a synthetic spoken call through the deployed worker. Check exact spoken prices, the first clarification, interruptions and tool latency. Credits or provider failures block this gate; a lookup-only pass cannot substitute for it.
5. **Capture:** export the call with `scripts/export-call-review.ts`. Verify intended identity, both speakers, contiguous sequence and expected/persisted counts. Provider text is generated speech, not proof all audio was heard. Keep recordings and transcript evidence private.
6. **Operations:** check `supervalu-positive-publication` in database cron run history for completion and errors. Verify the known source-to-publication cases after each refresh and each deployment. A running full scan is not an excuse to hide already verified offers; a green worker health check is not proof of offer completeness.

The app migration `supervalu_positive_publication` retains the completed-scan publisher and overlays positive evidence after it. A separate minute schedule publishes newly observed evidence during long scans, including the Thursday refresh. Both publishers share the same transaction lock. Positive publication is idempotent and does not remove unrelated rows. Anonymous and ordinary authenticated accounts cannot invoke either publisher.

Rollback regression coverage is in the app repository at `scripts/tests/supervalu-positive-publication.sql`. Load the prepared migration and regression in one transaction and always roll back. Fixtures carry `QA_POS_` / `[smoke test]` markers. The assertions cover running sources, expiry, future validity, failed sources, insufficient sources, stale evidence, price conflict, preservation and repeat publication.
